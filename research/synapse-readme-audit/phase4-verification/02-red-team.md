The verdict holds as "honest on every headline claim," but the exception list should have been four-to-six items, not two.

## Why the surviving Highs stay High, one line each

The audit's only High-severity residual threats are RT-2 (distributed decode is verifiably sound *in its gate* — `verify_speculative_tokens` accepts batch 0's token from true context `[last]` and batch *i*'s token only after batch *i-1* confirmed guess *i-1*, so no contaminated-context token can ever enter the output — but the output is a continuation of the last token, never the prompt) and RT-4 (the LACP path is now CLI-reachable and carries a per-forward O(0.5 s×N) partition cost plus standing probe churn; nothing about it is incorrect *as documented*, but it is unmeasured and undisclosed). RT-1/RT-3/RT-5 are disclosure/wording gaps, not behavioral falsehoods.

## Surgical fixes (research recommendations — not applied)

1. **RT-1/RT-8 — README:24:** replace `state recovered from JSON checkpoint (no pickle)` with `dead node's JSON checkpoint (no pickle) is written and staged for the survivor — resume-from-checkpoint pending (see Known Limitations)`. One line.
2. **RT-2 — add a Known Limitations bullet (~README:159):** "In distributed decode each micro-batch's context is the last token plus verified lookahead guesses, not the full prompt; the verification gate is sound but distributed output is not prompt-conditioned end to end."
3. **RT-3 — `p2p_socket_bridge.py:485`:** either raise the 10 MB cap to a negotiated frame limit with a size header, or disclose: "the bridge closes any connection whose JSON frame exceeds 10 MB (≈5 MB raw tensor after hex framing); large hidden states/long sequences can hit this silently." Prefer the disclosure (cheap) plus a `WARNING` log.
4. **RT-4 — `node.py:1664`:** gate the probe spawn on `now - getattr(self,'_last_probe_at',0) > 10` and cache the last matrix for the 2 s election-scorer refresh; re-run only on topology change. Also consider removing the 0.5 s disk sleep from the hot path (`resource_weight.py:137`) or caching disk metrics for a few seconds. Disclose the single-message bandwidth proxy (B-11).
5. **RT-5 — README:217:** append "(rebalance triggers only after the distributed pipeline has been initialized and after discovery drops the dead peer)". Optionally initialize `_distributed_pipeline` unconditionally in `node.start()` so the C-FT-5 gate is not request-dependent.
6. **RT-7 — `node_extension.py:113`:** change the swallow to log at WARNING, and gate the single-node 1F1B checkpoint (`:492`) on `world_size > 1`.
