## Per-lane analysis

**Lane A (decode/inference).** Both blockers are genuinely fixed and — critically — are now *covered by tests that cross the production transport boundary*, which is exactly what the lane said was missing. `test_binary_tensor_survives_bridge_roundtrip` runs two real `Libp2pNode`/`P2PSocketBridge` instances over real TCP sockets, publishes `{"bin": encode_tensor(...)}` through the real `EventRouter`, and decodes on the far side (I ran it: pass). The 1-D reshape guard (`distributed_engine.py:188–189`) directly addresses the empirically-reproduced `shape[1]` crash, and `test_onedimensional_encode_is_normalized` drives the real controller entry point. The fix holds. However, the lane's *Medium* findings 5, 7, 8, 9 were untouched: the decode loop still conditions on `[last] + guesses[:i]` with no prompt/KV carry-over, `_collect_result` still accepts any event on the result topic, and the token buffer still drops legitimate adjacent repeated tokens. With the two blockers fixed, **A-F8 (truncated context) is now the most dangerous residual**: a live multi-node run with a real model would produce tokens that are "verified" against a model that never saw the prompt. Flag for red-team.

**Lane B (partitioning/election).** The three Highs and the off-by-default path are all wired for real. The bridge's 5-byte peek + echo (with a 10 MB length heuristic that a `!dQ` timestamp always exceeds) makes the previously-impossible probe succeed, and the measured bandwidth now actually flows into the partitioner and the election scorer (`node.py:1647–1655` → `:1677` → `:1590`). The stickiness branch (`election.py:130–138`) is a clean fix and the new behavioral test reproduces the exact old failure mode (weight flip) and asserts no split-brain. The CLI flags (`main.py:79–80`) and constructor pass-through (`main.py:168–179`) make ILP and the multi-resource path genuinely selectable. Not addressed: `_latency_cache` staleness, the dead `broadcast_authoritative_partition` (so `_compute_lacp_partition` still re-runs per forward when the LACP path is enabled — now *reachable* via `--no-tflops-proportional`), and the vacuous ILP contiguity constraints. One interaction worth flagging: the stickiness fix keeps the master forever while it appears in `active_nodes` — combined with C-FT-4 (heartbeat is membership-derived), a master that dies but is not dropped by discovery will *never* be demoted. That is the mirror-image split-brain (silent unavailability) and was not tested.

**Lane C (fault tolerance / 1F1B / transports).** The dead `_pipeline_extension` branch is fixed with the real property, and the new test drives the actual API method end-to-end (I ran it: pass, with the `enqueue_example` fallback asserting-fail). Checkpoint writes are now wired into both training paths including the single-node early return, and the two new tests assert real `.ckpt` files on disk (I ran them: pass). The 1F1B backward no-op and the "staged but never applied" recovery are **not** fixed in code, but the README now discloses both precisely (lines 68–69 and 158–159), and the shared-filesystem dependency is disclosed. Transports: README is honest; TCP and SHM are started on every node and peer-registered, but remain off the runtime data plane — this is now an accurate description of a real architectural state rather than an overclaim. **New-bug check on the fixes:** (a) `_save_shard_checkpoint` swallows every exception (only `DEBUG>=1` prints a traceback, `node_extension.py:113–115`) — a checkpoint-write failure silently produces no recovery state, so C-H1 can no-op without any signal; (b) the checkpoint written is metadata-only (`kv_cache=None`), which the README correctly says, so "recovered from JSON checkpoint" buys the survivor layer-range/step metadata, not weights; (c) the single-node 1F1B early return now writes a checkpoint on every step with the same `try/except` — on long single-node runs this is disk chatter with zero recovery benefit. None are correctness regressions.

**Lane D (README truthfulness).** Every substantive claim now matches repo facts, which I verified independently: route registrations (`chatgpt_api.py:352,354,388`), `source_stage_id` in `result_router.py`, absence of the phantom routes / `sequence_position` / "msgpack header" / "≤32 nodes" (greps), the honest 1F1B and checkpoint disclosures, and the "no source-string assertion tests" claim (no `getsource` in `backend/tests`; the single `inspect.signature` is behavioral). Test counts: **220 tests exact** (pytest-collected), per-file counts all exact (16/16), but **modules = 29, not 30** — a one-line README overcount. Everything else the lane flagged (hundreds-of-nodes marketing, npm launcher in root `main.py`, `lacp3` test names, unenforced benchmark↔README invariant) is a Note and unchanged.

## Anything the lanes missed

1. **Module count off by one (D-H8).** "220 tests across 30 test modules" should read 29. Verified by `pytest --collect-only`: 220 items from 29 modules (the nine runner scripts with zero `def test_` are correctly excluded).
2. **Checkpoint-write failure is silent (C-H1 caveat).** The new `_save_shard_checkpoint` swallows all exceptions below `DEBUG>=1`; in production a failing checkpoint directory yields no error, no log, and no recovery state.
3. **Probe storm under the now-selectable LACP path.** `_build_latency_matrix` fires a background `probe_peers_background()` task on *every* call (each opening a TCP connection the bridge echoes then closes), and the election scorer invokes it every 2 s via `_refresh_election_weight` (`node.py:1547`). With `--no-tflops-proportional` this becomes a standing per-node connection churn. Efficiency concern, not yet measured.
4. **Bridge probe heuristic edge.** Any frame with a length field >10 MB is now echoed back as a "probe" and the connection closed; a misbehaving client sending a huge declared length gets an echo instead of a dropped connection. Bounded by the 5 s timeouts; benign but worth noting.
5. **Stickiness + membership-derived heartbeat interaction** (see Lane B above): a dead-but-listed master is never demoted — the split-brain fix inverted into a potential no-master-on-death scenario for discovery sources that do not drop dead peers.
